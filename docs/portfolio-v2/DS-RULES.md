# Дизайн-система портфолио v2

## Источник истины

Общий источник — `src/portfolio/tokens.ts`, `ui.tsx` и `portfolio.css`. `App.tsx` импортирует эти реализации для обычных страниц и `/ds/`; `entry-server.tsx` рендерит тот же `PortfolioApp` в HTML. Общий импорт подтверждает переиспользование кода, но не заменяет сравнение в браузере.

`tokens.ts` разделяет палитру и семантические роли: текст, вторичный текст, фон, поверхность, акцент, границы и инверсный контактный блок. Там же находятся типографическая шкала, интервалы, радиусы, контейнеры и параметры движения. `tokenCss` публикует CSS-переменные. Локальная композиция страниц находится в CSS. Не добавлять независимую копию роли или значения только для `/ds/`.

Одна светлая тема с инверсным footer. Стек шрифта содержит Manrope и системные sans-serif fallback; отдельного загрузчика шрифтов нет. Синхронизация с Figma и Code Connect не настроены.

## Контракты

| Компонент | Назначение и данные | Варианты и ограничения |
| --- | --- | --- |
| `Button` | Действие без `href`; навигация при наличии `href`; содержательное имя задаёт `children` | `primary`, `secondary`, `ghost`; размеры `md`/`sm`. API содержит `danger`, не используемый основными страницами. `disabled` и `loading` блокируют действие; loading задаёт `aria-busy`. Ссылка не получает фиктивный `role=button` |
| `Icon` | Выбранный символ из `lucide-react` | Единый stroke; по умолчанию `aria-hidden`, `focusable=false`. Самостоятельному иконочному действию имя задаёт родитель |
| `Badge` | Короткий тип, тег или статус | `neutral`, `blue`, `green`, `amber`. Не подменяет кнопку или интерактивный фильтр |
| `CaseCard` | Slug, заголовок, summary, категория, роль, стадия, обложка, alt, URL | Featured и обычная карточка. Временная обложка помечается `placeholder`; весь переход остаётся обычной ссылкой |
| `Media` | Иллюстрация, alt и подпись | Временный материал маркируется; `priority` задаёт eager/high для первого изображения кейса. `srcSet` можно передать явно. При ошибке картинки показывается текстовый fallback |
| `Header` / `Footer` | Общая навигация и подтверждённые контакты | Внутренние URL через `hrefFor(basePath, path)`; внешние контакты без base. Header содержит skip-link; footer использует инверсные роли |
| `ArticleBlock` | Заголовок и абзац раздела кейса | Одна реализация в кейсе и `/ds/`, без отдельной декоративной копии |
| `CopyEmailButton` | Копирование публичного email | `idle → copying → copied` только после успешного `writeText`. При отказе — readonly-поле для ручного копирования; успех озвучивается через `role=status` |
| `Container` / `Section` | Общие контейнеры и смысловые секции | Не заменяют семантическую структуру страницы; секциям нужны понятные заголовки/метки |

Поля используют общую CSS-пару `.sp-field` / `.sp-input`, без отдельной библиотеки форм. Реальные потребители — ручной fallback копирования и селект страницы в адаптивном preview. Стиль `aria-invalid` не означает наличия отправляемой формы или backend-валидации.

## Матрица источников и потребителей

Ниже — аудит кода. Фактические браузерные, клавиатурные и визуальные результаты записываются в [PLAN.md](../../PLAN.md) и [acceptance.json](acceptance.json). Эта таблица не объявляет их пройденными.

Текущий браузерный проход проверил desktop главной и `/ds/`, переход из главной в кейс внутри iframe и отказ Clipboard API: показано readonly-поле ручного копирования. В режимах iframe 390/768 измерены clientWidth документа 375/753 CSS px, горизонтального переполнения не обнаружено. Успешный Clipboard, WebKit и физическое устройство не проверены. Эти наблюдения не закрывают остальные сценарии матрицы.

## Движение и доступность

- Цвета/границы используют общие `180ms`, easing `cubic-bezier(.2,.65,.3,1)`.
- Обложка CaseCard масштабируется до `1.025` по hover; переход `500ms` с общим easing. Уход курсора возвращает исходное состояние; бесконечного цикла нет.
- Spinner есть только во время loading; после завершения операции исчезает вместе с этим состоянием. Он не блокирует чтение страницы.
- При `prefers-reduced-motion: reduce` переходы и анимации сокращаются, масштаб обложки отключается; основной контент остаётся видимым.
- Есть `focus-visible`, нативные ссылки/кнопки, alt и CSS для forced-colors. Наличие правил в CSS не считается ручным прохождением сценария.

## Правила изменения

1. Найти существующий компонент и потребителей. Сначала переиспользование, затем обоснованный вариант; новый компонент — при отдельной устойчивой задаче.
2. Роль/токен менять в `tokens.ts`, общее поведение и геометрию — в источнике UI. Не исправлять сгенерированный `dist/`.
3. Обновить пример `/ds/` и матрицу затронутого контракта. Уникальная иллюстрация не обязана становиться компонентом.
4. Выполнить build и `check:pages`; проверить потребителей и `/ds/` в одинаковом окружении, включая относящиеся к правке ошибки и reduced-motion.
5. Результаты, исключения и ограничения записать в PLAN. Имитация hover не заменяет настоящее событие.

`/ds/` доступна прямым URL, получает `noindex` и не входит в sitemap. Это документация, не закрытое хранилище. Аналитика не выбрана; при её добавлении маршрут исключается из сбора до первых тестов.
